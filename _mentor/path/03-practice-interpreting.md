<div class="mp-section">
  <h2>本阶段目标</h2>

  <h3 class="no_toc" style="font-size:15px;color:#1e40af;margin:0 0 8px;">学生要完成</h3>
  <ul class="mp-goals">
    <li>在真实口译实习或学院组织的<strong>模拟会议口译</strong>中，同步录下原语与自己的译语，作为可分析语料。</li>
    <li>把录音整理成可检索的文字资产：转写、对齐、必要时建记忆库与术语表。转写规模须达到学院要求（不少于 10,000 汉字 / 英语单词）。</li>
    <li>从自己的口译实践中找出一个<strong>值得探究的问题</strong>——可以是某类翻译难点，也可以是自己的语言转换习惯——并凝结成可分享的案例。</li>
    <li>在做实践的同时，尽早明确自己倾向使用的分析框架。口译方向要比笔译更早进入理论选择，否则后期总结技巧时容易无章可循。</li>
  </ul>

  <h3 class="no_toc" style="font-size:15px;color:#1e40af;margin:16px 0 8px;">导师关注</h3>
  <ul class="mp-goals">
    <li><strong>问题是否来自实践</strong>：报告是否体现「发现问题—解决问题」的经验，而不是用现成理论套一套录音。</li>
    <li><strong>理论是否有针对性</strong>：是否过早、过窄地锁死在几本经典口译理论上；场景特征（商务、法律、能源等）是否需要跨学科视角。</li>
    <li><strong>Implementation 是否有项目管理思维</strong>：语料数字化、流程设计、质控与改进点是否写得出来。这同样是论文质量的关键部分。</li>
  </ul>
</div>

<div class="mp-section">
  <h2>学院基本要求（口译实践报告）</h2>
  <ul class="mp-goals">
    <li>在导师指导下，对自己承担的口译任务进行描述和分析。</li>
    <li>附录：不少于 <strong>10,000 汉字 / 英语单词</strong>的口译录音转写。</li>
    <li>正文：不少于 <strong>5,000 英语单词</strong>的分析报告。</li>
    <li>内容通常包括：任务描述、任务过程、案例分析、实践总结。</li>
  </ul>
  <p style="color:#64748b;margin:12px 0 0;">教指委另要求音视频支撑材料时长 30 分钟以上（含原语与译语）。涉密无法出示录音的，须由保密方出具签字盖章说明。</p>
</div>

<div class="mp-section">
  <h2>语料从哪里来</h2>
  <p style="margin:0 0 12px;">优先真实实习：把会议原声和自己的口译都录下来。并非每位同学都有会议口译机会，学院组织的多次模拟会议口译，其录音同样可以作为实践报告语料。无论真会还是模拟，关键是<strong>原语 + 译语成对保存</strong>，并能对应到具体场次、角色与主题。</p>
</div>

<div class="mp-section">
  <h2>建议的语料工作流</h2>
  <p style="font-size:14px;color:#94a3b8;margin:0 0 12px;">职业口译员不仅要有知识储备和语言转换能力，还要能做商务沟通、行程管理和语言资产管理。语料整理做到哪一步，以你的研究问题为准；能自动化、用 AI 辅助的环节，尽量自动化。</p>
  <ol class="mp-list">
    <li><strong>采集</strong>：原语与译语分轨或可区分地录音；记下会议类型、听众、主题、准备材料与突发情况。</li>
    <li><strong>转写</strong>：语音转文字后人工校对。转写是后续分析的底稿，也是附录的主体。</li>
    <li><strong>对齐</strong>：按意群或句段把原语与译语对齐，便于定位难点、对比处理策略。</li>
    <li><strong>资产化（按需）</strong>：导入记忆库、抽取术语、整理译前准备资料。这些既服务当下口译，也为语言资产 / 项目管理类报告留空间。</li>
    <li><strong>观察流程</strong>：转写不准、切分困难、术语前后不一致、准备材料没用上——这些都是 Implementation 里可写的改进点。</li>
  </ol>
</div>

<div class="mp-section">
  <h2>Best Practice</h2>
  <div class="mp-qa">
    <h4 class="no_toc">案例要能分享「你怎么处理的」，而不是只证明「很难」</h4>
    <p>值得写的问题，通常来自你自己的实践：某类数字/引语/文化负载词反复卡住，或你习惯先抓主干再补细节、却在某类发言里失效。把问题说清楚，把当时的处理、事后的改进写清楚，案例才有行业参考价值。</p>
  </div>
  <div class="mp-qa">
    <h4 class="no_toc">理论框架要早选，但不必扎堆用同一套经典口译理论</h4>
    <p>口译理论建立时间不长，常用框架有限。全班都用同一套经典理论，创新性往往不高。商务会议、法律、能源等场景里，传播、文化、国别研究、信息传递等跨学科理论，有时更能解释「听众听到了什么、为什么这样处理」。实践时就带着框架去观察，后期总结才有章可循。</p>
  </div>
  <div class="mp-qa">
    <h4 class="no_toc">Implementation 仍然是加分项</h4>
    <p>评阅时同样看重：你如何把语音变成可管理的文字资产、如何设计准备与复盘流程、如何用自动化或 AI 优化转写和对齐。写清「流程中发现了什么问题、怎么改」，比只写「我做了交替传译」更有专业度。</p>
  </div>
</div>

<div class="mp-section">
  <h2>Q&amp;A</h2>
  <div class="mp-qa">
    <h4 class="no_toc">Q1 · 没有会议口译实习，模拟会议能写实践报告吗？</h4>
    <p>可以。学院组织的模拟会议口译录音，可以作为语料。仍须满足转写篇幅与音视频时长要求，并在任务描述里交代模拟的场景设定与自己承担的任务。</p>
  </div>
  <div class="mp-qa">
    <h4 class="no_toc">Q2 · 转写必须自己逐字敲完吗？可以用语音识别吗？</h4>
    <p>可以用识别工具做初稿，但必须人工校对。报告里应说明工具、校对原则（如口误、重叠发言如何处理）。转写质量直接影响案例分析是否站得住。</p>
  </div>
  <div class="mp-qa">
    <h4 class="no_toc">Q3 · 口译方向是不是不能写项目管理或语言资产类报告？</h4>
    <p>可以写。口译实践同样涉及术语准备、语料对齐、行程与任务管理。若研究问题落在资产或流程上，类型选择仍以 <a href="{{ site.baseurl }}/mentor-platform/path/01-topic/">01 选题定向</a> 的六类为准，不必自我限定为「口译实践操作类」。</p>
  </div>
  <div class="mp-qa">
    <h4 class="no_toc">Q4 · 理论要在实践之前就定死吗？</h4>
    <p>不必定死，但要尽早有候选。带着一两个框架去听自己的录音，比实践全部结束再找理论贴标签更有效。若发现经典口译理论解释力不足，应主动看跨学科文献，并与导师确认可行性。</p>
  </div>
</div>

<div class="mp-section">
  <h2>自查清单</h2>
  <ul class="mp-check">
    <li>已有成对的原语 / 译语录音，来源是真实实习或学院模拟会议，场次信息可说明</li>
    <li>转写达到不少于 10,000 汉字 / 英语单词；音视频时长满足教指委 30 分钟以上要求（或已有保密说明）</li>
    <li>原语与译语已对齐，难点片段能定位</li>
    <li>已从实践中收窄出一个可分析的问题，而不是「提升口译质量」这类空目标</li>
    <li>已有理论 / 分析框架的候选，并考虑过是否需要跨学科视角</li>
    <li>过程记录能说明：如何转写、如何对齐、用了哪些工具、流程上发现了什么问题</li>
  </ul>
</div>
